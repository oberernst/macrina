# Macrina 1.0 Release Plan

This is the working plan for turning Macrina into a useful open source 1.0 CoAP library.
It is intended for future agents and human contributors.

## Product Direction

Macrina 1.0 should be an Elixir-first CoAP library with:

- a clean public API built around client, server, request, and response concepts
- strict RFC 7252 core behavior over UDP
- RFC 7959 blockwise transfer support
- RFC 7641 observe support
- discovery support for `/.well-known/core`
- telemetry events instead of library-owned logging
- enough interop coverage to be trusted in public open source use

Macrina 1.0 should not block on DTLS, OSCORE, CoAP-over-TCP, HTTP proxying, or broad extension RFC coverage.
Those should be designed for, but not required for the first stable release.

## Principles

- Prefer correctness over early feature breadth.
- No backwards compatibility constraints from the current pre-1.0 surface.
- Public APIs should be typed, intentional, and hard to misuse.
- Public APIs should return tagged tuples by default and reserve raising behavior for explicit `!` variants.
- Prefer data over processes where practical and keep effectful shells thin.
- Prefer left-aligned code: name intermediate values, avoid function calls inside tuple literals, and treat deep indentation as a smell.
- Internal transport details should not leak into normal application code.
- Telemetry is emitted by the library; logging and tracing are application concerns.
- Interop is a release gate, not a future aspiration.

## Proposed 1.0 Module Map

### Public modules

- `Macrina.Client`
  - Owns request lifecycle from application code.
  - Exposes `connect/1`, `request/2`, and convenience helpers like `get/2`.
- `Macrina.Server`
  - Public server entrypoint.
  - Starts UDP serving and later hides endpoint/exchange implementation details.
- `Macrina.Router`
  - Behavior for request routing and response generation.
  - Receives `Macrina.Request` plus server context.
- `Macrina.Request`
  - High-level request struct.
  - Responsible for URI decomposition and option generation.
- `Macrina.Response`
  - High-level response struct.
  - Stable application-facing representation of replies.
- `Macrina.Telemetry`
  - Canonical source of library event names.
  - Thin wrapper around `:telemetry.execute/3` and `:telemetry.span/3`.

### Internal modules

- `Macrina.Codec`
  - Packet encoding and decoding.
  - Strict message validation.
- `Macrina.Exchange`
  - Message IDs, tokens, retransmission, deduplication, exchange lifetimes.
- `Macrina.Blockwise`
  - Block1 and Block2 logic and transfer state.
- `Macrina.Observe`
  - Observe relationship management.
- `Macrina.Transport.UDP`
  - UDP socket ownership, send and receive.
- `Macrina.Server.Dispatch`
  - Bridges decoded requests into router calls and serializes responses.

The current modules `Macrina.Endpoint`, `Macrina.Connection`, and `Macrina.Connection.Server` should become internal implementation details or disappear entirely.

## Public API Draft

### Client API

```elixir
{:ok, client} = Macrina.Client.connect(ip: {127, 0, 0, 1}, port: 5683)

{:ok, request} = Macrina.Request.from_uri(:get, "/temperature")
{:ok, response} = Macrina.Client.request(client, request)

response.code
response.payload
```

Convenience usage:

```elixir
{:ok, client} = Macrina.Client.connect(ip: {127, 0, 0, 1}, port: 5683)
response = Macrina.Client.get(client, "/temperature?unit=c")
```

### Server API

```elixir
defmodule Demo.Router do
  @behaviour Macrina.Router

  @impl true
  def call(%Macrina.Request{method: :get, path: ["temperature"]}, _context) do
    Macrina.Response.new(:content,
      payload: "22.3 C",
      options: [{"Content-Format", 0}]
    )
  end

  def call(_request, _context) do
    Macrina.Response.new(:not_found)
  end
end

{:ok, _server} = Macrina.Server.start_link(port: 5683, router: Demo.Router)
```

The current codebase still routes through the older handler pipeline.
The 1.0 path is to make `Macrina.Server` the stable entrypoint and phase out direct `Endpoint` usage.

## Telemetry Contract

Macrina should emit a small, stable set of events with low-cardinality metadata.

### Current starter events

- `[:macrina, :app, :start]`
- `[:macrina, :endpoint, :start]`
- `[:macrina, :endpoint, :packet, :received]`
- `[:macrina, :endpoint, :udp, :error]`
- `[:macrina, :endpoint, :connection, :start, :error]`
- `[:macrina, :connection, :start]`
- `[:macrina, :connection, :stop]`
- `[:macrina, :connection, :decode, :error]`
- `[:macrina, :connection, :request, :encode, :error]`
- `[:macrina, :connection, :reply, :sent]`
- `[:macrina, :connection, :reply, :encode, :error]`
- `[:macrina, :connection, :reply, :build, :error]`
- `[:macrina, :connection, :reply, :skipped]`
- `[:macrina, :connection, :reply, :resent]`
- `[:macrina, :connection, :block, :received]`
- `[:macrina, :connection, :block, :continue]`
- `[:macrina, :connection, :block, :assembled]`
- `[:macrina, :connection, :block, :completed]`
- `[:macrina, :connection, :block, :missing]`
- `[:macrina, :connection, :block, :incomplete]`
- `[:macrina, :exchange, :dedup, :hit]`
- `[:macrina, :exchange, :retransmit]`
- `[:macrina, :exchange, :timeout]`
- `[:macrina, :server, :router, :error]`
- `[:macrina, :client, :request, :start]`
- `[:macrina, :client, :request, :stop]`
- `[:macrina, :client, :request, :exception]`

### Planned 1.0 events

- `[:macrina, :codec, :decode, :exception]`
- `[:macrina, :blockwise, :request, :start]`
- `[:macrina, :blockwise, :chunk, :sent]`
- `[:macrina, :blockwise, :chunk, :received]`
- `[:macrina, :observe, :register]`
- `[:macrina, :observe, :notify]`
- `[:macrina, :observe, :cancel]`

### Measurement and metadata rules

- Use native-time durations for span events.
- Prefer numeric measurements such as `bytes`, `duration`, `count`, `block_number`, and `block_size`.
- Prefer metadata such as `method`, `code`, `type`, `path`, `peer`, `content_format`, and `error`.
- Never log inside telemetry handlers from the library itself.
- Do not include large payloads in telemetry metadata.

## Milestone Backlog

### Milestone 1: API reset and telemetry base

Work:

- Add `Macrina.Request`, `Macrina.Response`, `Macrina.Server`, `Macrina.Router`, and `Macrina.Telemetry`.
- Move new application-facing examples and docs to the new surface.
- Replace logger usage on touched paths with telemetry.

Acceptance criteria:

- New request and response types exist and compile.
- Client helpers route through `Macrina.Request` and return `Macrina.Response`.
- The repo contains a documented telemetry contract.
- No new public examples require direct use of `Macrina.Endpoint`.

### Milestone 2: codec correctness

Work:

- Fix payload marker emission.
- Enforce empty message and token-length rules.
- Clean up reset naming and reserved type handling.
- Add structured decode and encode validation errors.

Acceptance criteria:

- Packet fixtures cover empty, request, response, and malformed cases.
- Invalid TKL and payload-marker cases are rejected.
- Round-trip tests pass for supported message forms.

### Milestone 3: exchange engine

Status:
Completed.

Work:

- Add exchange state independent of peer process state.
- Implement confirmable retransmission and ACK timeout.
- Implement deduplication keyed by endpoint and MID.
- Support piggybacked and separate responses correctly.

Acceptance criteria:

- Confirmable requests retransmit and stop on ACK or RST.
- Duplicate inbound CON requests are detected and handled deterministically.
- Message ID and token state are tracked per exchange lifetime.

### Milestone 4: URI and option semantics

Work:

- Implement proper CoAP URI decomposition and normalization.
- Add typed option helpers for content format, accept, max-age, observe, and block options.

Acceptance criteria:

- Absolute and relative request URIs decompose correctly.
- Host and port options are emitted only when appropriate.
- Query and path handling is RFC-aligned for supported cases.

### Milestone 5: blockwise transfers

Work:

- Move block state from per-peer storage to exchange-aware state.
- Support client-side Block2 reassembly.
- Support server-side Block1 atomic and streaming modes.
- Enforce content-format and sequence rules.

Acceptance criteria:

- Block2 downloads reassemble full payloads.
- Block1 uploads support 2.31 and 4.08 behavior.
- Blockwise tests cover size negotiation and incomplete transfers.

### Milestone 6: server routing and discovery

Work:

- Build router dispatch around `Macrina.Router`.
- Add `.well-known/core` discovery helpers.
- Support content-format aware responses from the server path.

Acceptance criteria:

- A minimal router-based server can serve multiple resources.
- Discovery responses are available and documented.

### Milestone 7: observe

Work:

- Add observe registration, cancellation, and notification flow.
- Coordinate observe with Block2 responses.

Acceptance criteria:

- Observe client and server happy paths are covered by integration tests.
- Notifications preserve response correlation and telemetry visibility.

### Milestone 8: release hardening

Work:

- Add interop tests and example applications.
- Publish HexDocs-quality guides.
- Add changelog, contribution guide, and security policy if missing.

Acceptance criteria:

- The support matrix is explicit.
- The release candidate has passing tests and documented known limitations.
- A new user can build a server and client from the docs without reading internal modules.

## Immediate Execution Plan

The first implementation pass should do three things:

1. Land this document and establish the target 1.0 module map and API draft.
2. Translate the roadmap into milestone-by-milestone work with acceptance criteria.
3. Begin the refactor by introducing the new public request, response, server, and telemetry surface before deeper protocol work starts.
